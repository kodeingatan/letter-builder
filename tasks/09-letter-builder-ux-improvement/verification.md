## Open Questions

- Apakah `409` sebaiknya divisualkan sebagai **`NAlert type="warning"` (kuning) atau `NAlert type="error"` (merah)**? Design `08/conflict.svg` memakai warning `#FFFBEB`/`#FDE68A` (kuning) — `09` wire memakai `warning` agar beda dari 500 `error`; jika review memilih `error`, cukup ganti prop tanpa ubah Test ID.
- Perlu `inline link "Lihat → /dashboard/templates/:id"` di `ReferenceList` untuk semua tipe reference (`template:*`, `component:*`, `pegawai:column`)? Saat ini `component:*` link ke `/dashboard/components?search=<name>` dan `pegawai:column` ke `/dashboard/master-data/<slug>` — apakah deep-link ke baris/kolom spesifik (query `?highlight=col`) diperlukan?
- `findReferences` via `String.includes` exact (`"componentId":"<name>"`) cukup atau perlu `JSON.parse(schemaJson)` + traversal tree untuk akurasi 100% (EC-10)? Traversal lebih presisi tetapi cost `O(n*m)` vs `includes O(n)` — benchmark 200 templates × 200 nodes?
- `document_number` duplicate 409 apakah lebih baik inline `NFormItem` merah di wizard field daripada modal `ReferenceList`? Contract runs mengembalikan `409` + message — wizard field `document_number` bisa focus + `validationStatus="error"`.
- Butuh `DELETE /api/master-data/:slug/columns/:name` granular atau tetap via `PUT` `syncColumns` diff? Saat ini 409 column via `PUT` remove — granular delete belum ada; apakah perlu endpoint baru untuk akurasi `ReferenceList` per-kolom?
- Apakah `ReferenceList` modal perlu `pagination` bila `references` >50 (mis. Master Table dipakai 50 template)? Atau cukup `NScrollbar max-height 320px` + `virtual scroll` + `search filter` di modal?
- `NPopconfirm` delete → 409 modal flow: apakah `NPopconfirm` tetap dipakai sebagai guard awal atau diganti langsung `NDialog confirm` yang bisa switch ke `ReferenceList` bila 409 (tanpa double modal)? UX double-modal bisa jarring.
- `Puppeteer` install di CI: tetap `PUPPETEER_SKIP_DOWNLOAD=1` + `npx playwright install chromium` atau `npm install puppeteer --force` + `Xvfb`? Decision env `HEADLESS=1` vs `CI=true` existing di `playwright.config.ts` — perlu `STORAGE_DIR` write test?
